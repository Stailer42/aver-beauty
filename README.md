# AVER: демо-сайт салона красоты

Тестовый сайт для портфолио. Две страницы: лендинг (`index.html`) и онлайн-запись (`booking.html`), плюс админка (`admin/`).
Все имена, цены, отзывы, адрес, e-mail и телефоны **выдуманы**. Телефоны в нерабочем формате `+380 00 000 00 00`.

Технологии: обычные HTML + CSS + JavaScript. Ничего не нужно устанавливать и собирать.

## Как запустить у себя

Нужен локальный сервер (Python 3 на Mac уже есть). Двойной клик по `index.html` больше не подходит: браузеры не дают базе данных и шифрованию пароля работать с `file://`.

```bash
cd /Applications/aver.beauty
python3 serve.py
```

Почему `serve.py`, а не `python3 -m http.server`: стандартный сервер держит в очереди только 5 соединений и обрывает остальные. Админка грузит больше десятка файлов сразу, и примерно в 1 случае из 13 какой-то файл не доходил, админка зависала на заставке. `serve.py` (та же стандартная библиотека Python, ничего ставить не надо) это исправляет и отключает кэш, чтобы после правок браузер брал свежие файлы.

- Сайт: http://localhost:8000
- Админка: http://localhost:8000/admin/ (демо-вход: логин `admin`, пароль `aver-demo`)

Остановить сервер: `Ctrl + C` в терминале.

## Админка

Работает прямо в браузере, без сервера и внешних сервисов. Данные хранятся в базе браузера (IndexedDB), поэтому:
- изменения видны **только в том браузере**, где их сделали; другой посетитель видит свою копию тестовых данных;
- пароль хранится только как хеш (PBKDF2-SHA256), но вход в статичном демо не настоящая защита: его можно обойти через инструменты разработчика. Настоящую защиту даст Supabase (см. ниже);
- «Налаштування → Скинути демо-дані» возвращает всё к тестовым данным, «Завантажити копію» сохраняет все данные в JSON-файл.

Разделы:
- **Записи**: список с фильтрами и поиском, календарь по мастерам, создание, подтверждение, отмена, перенос. Счётчик новых записей в меню.
- **Послуги**: категории, цены, длительность, описание, доплаты, показать/скрыть, порядок.
- **Майстри**: фото, роль, специализация, опыт, какие услуги делает, рабочие дни.
- **Розклад**: часы салона, праздники и сокращённые дни, настройки онлайн-записи, рабочие дни мастеров.
- **Фото**: работы (с точкой кадрирования) и зоны салона, загрузка, порядок.
- **Відгуки**: добавить, изменить, показать/скрыть, порядок.
- **Тексти й контакти**: первый экран, заголовки разделов, история, «Чому AVER», телефоны, адрес, соцсети.
- **Налаштування**: смена пароля, резервная копия, сброс демо-данных.

Админкой удобно пользоваться с телефона: снизу панель разделов, формы открываются шторкой.

Фото браузер сам сжимает перед сохранением (мастера до 800px, галерея до 1600px, WebP), так что можно загружать прямо с телефона. Место для фото в браузере ограничено (обычно сотни мегабайт), для демо этого с запасом.

## Проверки

Логика расписания (свободное время, пересечения, цена с доплатами), без браузера:

```bash
node --test tests/
```

Сценарии в headless Chrome, при запущенном сервере на порту 8765 (`python3 serve.py 8765`):

```bash
node tests/e2e/screens.mjs tmp/screens/new tmp/screens/before   # скриншоты сайта и сравнение попиксельно
node tests/e2e/admin-stage1.mjs                                 # вход, пароль, сессия, копия, сброс
node tests/e2e/admin-stage2.mjs                                 # услуги и мастера: правка в админке видна на сайте
node tests/e2e/admin-stage3.mjs                                 # записи и расписание, запрет двойной записи
node tests/e2e/admin-stage4.mjs                                 # фото, отзывы, тексты и контакты → сайт
```

Нужны Node 22+ и Google Chrome. Ничего ставить через npm не нужно.

## Как выложить в интернет бесплатно (GitHub Pages)

Репозиторий должен быть **публичным**: на бесплатном тарифе GitHub Pages работает только с публичными.

В этой папке git уже настроен, коммиты есть. Если будешь делать так же с новой папкой, сначала:
`git init -b main && git add . && git commit -m "Перша версія"`.

```bash
cd /Applications/aver.beauty
gh repo create Stailer42/aver-beauty --public --source=. --remote=origin --push
gh api -X POST repos/Stailer42/aver-beauty/pages -f "source[branch]=main" -f "source[path]=/"
```

Через 1-2 минуты сайт откроется по адресу: https://stailer42.github.io/aver-beauty/

Обновить сайт после правок:

```bash
git add .
git commit -m "Что поменял"
git push
```

Если репозиторий будет называться иначе, поправь адреса в `og:url` и `og:image` в `<head>` обеих страниц.

## Где менять цены, тексты и фото

Всё в админке (список разделов выше). Главная и форма записи берут данные оттуда. Разметка с текстами в `index.html` осталась как запасной вариант: её видят поисковики и посетители, если скрипты не загрузились.

Начальные тестовые данные лежат в `seed.js`. После правки `seed.js` увеличь `SEED_VERSION` в `db-local.js` (или нажми «Скинути демо-дані» в админке), иначе браузер продолжит показывать старую копию из своей базы.

## Как работает запись сейчас (демо)

- При первом запуске `seed.js` создаёт тестовые записи на неделю назад и две недели вперёд (вымышленные клиенты, телефоны `+380 00 000 …`).
- Свободное время считает `schedule.js` по часам салона, исключениям (праздники, сокращённые дни), рабочим дням мастера и уже существующим записям. Одна и та же функция работает на сайте и в админке.
- Клиент выбирает мастера или «Будь-який майстер». Во втором случае время показывается, если свободен хоть кто-то, а при сохранении назначается первый свободный.
- **Главное правило:** два активных (не отменённых) записи к одному мастеру не пересекаются по времени. Проверка и сохранение идут в одной транзакции базы, поэтому две вкладки, нажавшие «Записатися» одновременно, не пройдут обе. В Supabase то же правило стоит в самой базе (`bookings_no_overlap` в `schema.sql`).
- Цену, длительность и описание параметров при сохранении считает `data.js` по данным услуги, а не берёт со страницы.
- Новая запись с сайта получает статус «нова» и сразу видна в админке (счётчик возле «Записи» обновляется даже без перезагрузки, если админка открыта в соседней вкладке).
- Админ может записать клиента вне рабочих часов (админка переспросит), но не на занятое время мастера.
- «Сегодня» и «уже прошедшее время» считаются по часам на устройстве, а не по киевскому времени. Для демо это нормально; в Supabase функция `create_booking` считает по Europe/Kyiv.
- Очистить тестовые записи: админка → «Налаштування» → «Скинути демо-дані».

## Как подключить настоящую базу (Supabase)

Сейчас каждый браузер хранит свою копию данных. С Supabase (бесплатный тариф) данные станут общими: клиент записался на сайте с телефона, администратор видит запись в админке на ноутбуке.

Весь код работает с данными только через объект `AVERDB` из `db-local.js`. Для Supabase пишется `db-supabase.js` с теми же функциями и подключается вместо `db-local.js` в трёх страницах (`index.html`, `booking.html`, `admin/index.html`). Остальные файлы не меняются.

> Честно: `schema.sql` и план ниже написаны без доступа к живому Supabase и не запускались. Перед реальным запуском проверь на тестовом проекте.

**1. Проект и таблицы**
1. Зарегистрироваться на supabase.com → New project (регион поближе, например Frankfurt).
2. SQL Editor → вставить весь `supabase/schema.sql` → Run. Создадутся те же таблицы, что в демо, плюс:
   - `bookings_no_overlap`: сама база не даст двум активным записям к одному мастеру пересечься по времени (даже если двое нажмут «Записатися» в одну секунду);
   - права доступа (RLS): посетитель видит только видимые услуги, мастеров, фото, отзывы и тексты; записи с именами и телефонами видит и меняет только админ;
   - функции для сайта: `busy_slots(date)` (только занятые промежутки, без личных данных) и `create_booking(...)` (цену и мастера считает сервер);
   - бакет `photos` в Storage для фото.
3. Перенести тестовые данные: админка демо → «Налаштування» → «Завантажити копію», затем загрузить таблицы из JSON (Table Editor → Insert → Import, или небольшим скриптом). Таблицу `users` не переносить: пароли теперь хранит Supabase Auth.

**2. Администратор**
1. Authentication → Users → Add user: e-mail и пароль (Supabase хранит пароль как bcrypt-хеш на сервере).
2. SQL Editor: `insert into admins (user_id, name) values ('<id пользователя>', 'Адміністратор');`

**3. Код**
1. Подключить клиент Supabase перед своими скриптами:
   `<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2.45.4/dist/umd/supabase.js"></script>`
2. В `db-supabase.js` создать клиента: `supabase.createClient(URL, ANON_KEY)` (Project Settings → API). Публичный anon-ключ можно держать в коде: доступ ограничивают RLS-правила, а не секретность ключа. Ключ `service_role` в код сайта **никогда** не класть.
3. Реализовать функции `AVERDB` (у всех тот же смысл, что в `db-local.js`):

| Функция | В Supabase |
|---|---|
| `list(t)`, `get(t, id)`, `single(t)` | `from(t).select("*")`, `.eq("id", id).single()` |
| `put`, `putMany`, `saveSingle` | `from(t).upsert(row)` |
| `remove(t, id)` | `from(t).delete().eq("id", id)` |
| `atomic("bookings", fn)` | просто записать; пересечение отклонит база (ошибка `23P01`) → бросить ошибку с `code = "slot_taken"`, админка её уже обрабатывает |
| `busySlots(date)` | `rpc("busy_slots", { p_date: date })` |
| `createBooking(p)` | `rpc("create_booking", { p_service_id, p_master_id, p_date, p_start_min, p_choices, p_client_name, p_client_phone, p_comment })`, текст ошибки (`slot_taken` и др.) → `err.code` |
| `putFile(blob)`, `fileUrl(src)`, `removeFile(src)` | `storage.from("photos").upload(...)`, `getPublicUrl(...)`, `remove(...)`; в `src` хранить путь в бакете |
| `onChange(cb)` | Realtime: `channel("db").on("postgres_changes", ...)` (по желанию) |
| `exportAll`, `importAll`, `reset` | в Supabase не нужны: резервные копии делает сам Supabase; кнопки в «Налаштуваннях» убрать |

4. Вход: в `admin/auth.js` заменить проверку хеша на `supabase.auth.signInWithPassword({ email, password })`, `currentUser()` на `auth.getSession()` + проверку строки в `admins`, смену пароля на `auth.updateUser({ password })`, выход на `auth.signOut()`. Логин станет e-mail. Блокировку после неудачных попыток Supabase делает сам.
5. Время: в демо «сегодня» берётся из часов устройства. `create_booking` на сервере считает по Europe/Kyiv, так что запись «на прошедшее время» сервер отклонит, даже если у клиента сбиты часы.

## Что ещё заменить перед реальным запуском

- В админке: телефоны, e-mail, адрес, соцсети, тексты, мастера, цены, фото. Отзывы только настоящие. Блок для Google (`application/ld+json`) скрипт обновляет сам из контактов и расписания.
- В коде: запасные тексты в `index.html` (их видят поисковики до запуска скриптов), `<title>` и `meta description`, пометку «Демо-сайт» в футере, фото первого экрана и финального блока (`assets/photos/hero-*.jpg`, `cta.jpg`).
- Подключить Supabase (выше): без него каждый браузер видит свою копию данных, и записи клиентов до салона не дойдут.
