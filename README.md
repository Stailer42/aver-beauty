# AVER: демо-сайт салона красоты

Тестовый сайт для портфолио. Две страницы: лендинг (`index.html`) и онлайн-запись (`booking.html`), плюс админка (`admin/`).
Все имена, цены, отзывы, адрес, e-mail и телефоны **выдуманы**. Телефоны в нерабочем формате `+380 00 000 00 00`.

Технологии: обычные HTML + CSS + JavaScript. Ничего не нужно устанавливать и собирать.

## Структура

```
aver.beauty/
├── index.html      главная (лендинг)
├── booking.html    онлайн-запись
├── styles.css      все стили обеих страниц (админка тоже их использует)
├── script.js       общее: шапка, меню, анимации, переходы между страницами
├── booking.js      логика записи (шаги, свободное время, форма)
├── data.js         данные для страниц сайта: берёт их из базы и отдаёт страницам
├── db-local.js     "база данных" демо: IndexedDB в браузере (единственный файл, который знает, где лежат данные)
├── seed.js         ТЕСТОВЫЕ данные для первого запуска: услуги, цены, мастера, тексты, отзывы
├── typo.js         оформление текста: цены, длительность, телефоны, неразрывные пробелы
├── admin/          админка (/admin/): вход, разделы
├── supabase/       schema.sql: структура настоящей базы для переезда на Supabase
├── tests/e2e/      проверки в headless Chrome (скриншоты сайта, сценарии админки)
├── assets/
│   ├── photos/     сжатые фото для сайта (Pexels)
│   ├── favicon.svg иконка вкладки
│   └── og.png      картинка для превью ссылки в мессенджерах
└── README.md
```

## Как запустить у себя

Нужен локальный сервер (Python 3 на Mac уже есть). Двойной клик по `index.html` больше не подходит: браузеры не дают базе данных и шифрованию пароля работать с `file://`.

```bash
cd /Applications/aver.beauty
python3 serve.py
```

Почему `serve.py`, а не `python3 -m http.server`: стандартный сервер держит в очереди только 5 соединений и обрывает остальные. Админка грузит больше десятка файлов сразу, и примерно в 1 случае из 13 какой-то файл не доходил, админка зависала на заставке. `serve.py` (та же стандартная библиотека Python, ничего ставить не надо) это исправляет и отключает кэш, чтобы после правок браузер брал свежие файлы.

- Сайт: http://localhost:8000
- Админка: http://localhost:8000/admin/ (демо-вход: логин `admin`, пароль `aver-demo`)

Остановить сервер: `Ctrl + C` в терминале.

## Админка

Работает прямо в браузере, без сервера и внешних сервисов. Данные хранятся в базе браузера (IndexedDB), поэтому:
- изменения видны **только в том браузере**, где их сделали; другой посетитель видит свою копию тестовых данных;
- пароль хранится только как хеш (PBKDF2-SHA256), но вход в статичном демо не настоящая защита: его можно обойти через инструменты разработчика. Настоящую защиту даст Supabase (см. ниже);
- «Налаштування → Скинути демо-дані» возвращает всё к тестовым данным, «Завантажити копію» сохраняет все данные в JSON-файл.

Разделы появляются по этапам: 1) вход и настройки (готово), 2) услуги и мастера (готово), 3) записи и расписание (готово), 4) фото, отзывы и тексты.

Фото мастеров браузер сам сжимает перед сохранением (до 800px, WebP), так что можно загружать прямо с телефона.

## Проверки

Логика расписания (свободное время, пересечения, цена с доплатами), без браузера:

```bash
node --test tests/
```

Сценарии в headless Chrome, при запущенном сервере на порту 8765 (`python3 serve.py 8765`):

```bash
node tests/e2e/screens.mjs tmp/screens/new tmp/screens/before   # скриншоты сайта и сравнение попиксельно
node tests/e2e/admin-stage1.mjs                                 # вход, пароль, сессия, копия, сброс
node tests/e2e/admin-stage2.mjs                                 # услуги и мастера: правка в админке видна на сайте
node tests/e2e/admin-stage3.mjs                                 # записи и расписание, запрет двойной записи
```

Нужны Node 22+ и Google Chrome. Ничего ставить через npm не нужно.

## Как выложить в интернет бесплатно (GitHub Pages)

Репозиторий должен быть **публичным**: на бесплатном тарифе GitHub Pages работает только с публичными.

В этой папке git уже настроен, коммиты есть. Если будешь делать так же с новой папкой, сначала:
`git init -b main && git add . && git commit -m "Перша версія"`.

```bash
cd /Applications/aver.beauty
gh repo create Stailer42/aver-beauty --public --source=. --remote=origin --push
gh api -X POST repos/Stailer42/aver-beauty/pages -f "source[branch]=main" -f "source[path]=/"
```

Через 1-2 минуты сайт откроется по адресу: https://stailer42.github.io/aver-beauty/

Обновить сайт после правок:

```bash
git add .
git commit -m "Что поменял"
git push
```

Если репозиторий будет называться иначе, поправь адреса в `og:url` и `og:image` в `<head>` обеих страниц.

## Где менять цены и услуги

В админке: «Послуги» (категории, цены, длительность, описание, доплаты, показать/скрыть, порядок) и «Майстри» (фото, роль, услуги, рабочие дни). Главная и форма записи берут данные оттуда.

Начальные тестовые данные лежат в `seed.js`. После правки `seed.js` увеличь `SEED_VERSION` в `db-local.js` (или нажми «Скинути демо-дані» в админке), иначе браузер продолжит показывать старую копию из своей базы.

## Как работает запись сейчас (демо)

- При первом запуске `seed.js` создаёт тестовые записи на неделю назад и две недели вперёд (вымышленные клиенты, телефоны `+380 00 000 …`).
- Свободное время считает `schedule.js` по часам салона, исключениям (праздники, сокращённые дни), рабочим дням мастера и уже существующим записям. Одна и та же функция работает на сайте и в админке.
- Клиент выбирает мастера или «Будь-який майстер». Во втором случае время показывается, если свободен хоть кто-то, а при сохранении назначается первый свободный.
- **Главное правило:** два активных (не отменённых) записи к одному мастеру не пересекаются по времени. Проверка и сохранение идут в одной транзакции базы, поэтому две вкладки, нажавшие «Записатися» одновременно, не пройдут обе. В Supabase то же правило стоит в самой базе (`bookings_no_overlap` в `schema.sql`).
- Цену, длительность и описание параметров при сохранении считает `data.js` по данным услуги, а не берёт со страницы.
- Новая запись с сайта получает статус «нова» и сразу видна в админке (счётчик возле «Записи» обновляется даже без перезагрузки, если админка открыта в соседней вкладке).
- Админ может записать клиента вне рабочих часов (админка переспросит), но не на занятое время мастера.
- «Сегодня» и «уже прошедшее время» считаются по часам на устройстве, а не по киевскому времени. Для демо это нормально; в Supabase функция `create_booking` считает по Europe/Kyiv.
- Очистить тестовые записи: админка → «Налаштування» → «Скинути демо-дані».

## Как потом подключить настоящую базу

**Рекомендуемый путь: Supabase.** Структура базы уже готова в `supabase/schema.sql`: те же таблицы, что в демо, плюс запрет пересечения записей к одному мастеру на уровне базы, права доступа (RLS) и функции для сайта. Подробная инструкция появится на этапе 4. Суть: выполнить `schema.sql` в Supabase и заменить `db-local.js` на `db-supabase.js` с теми же функциями.

Ниже старый, более простой вариант через Google Таблицу (для двух функций `AVER.getBusySlots` и `AVER.saveBooking` в `data.js`). Админка с ним работать не будет.

**Самый простой бесплатный вариант: Google Таблица + Apps Script.**

1. Создать Google Таблицу. В первой строке написать заголовки: `date, category, start, duration, service, options, price, name, phone, comment, id, created` (скрипт пропускает первую строку). Столбец A (дата) перевести в формат «Обычный текст», иначе таблица превратит даты в свой формат.
2. «Расширения → Apps Script», вставить:

```js
function doGet(e) {
  const rows = SpreadsheetApp.getActiveSheet().getDataRange().getValues().slice(1);
  const busy = rows
    .filter((r) => r[0] === e.parameter.date && r[1] === e.parameter.cat)
    .map((r) => ({ start: Number(r[2]), end: Number(r[2]) + Number(r[3]) }));
  return ContentService.createTextOutput(JSON.stringify(busy)).setMimeType(ContentService.MimeType.JSON);
}

function doPost(e) {
  const b = JSON.parse(e.postData.contents);
  const id = "AV-" + Math.floor(1000 + Math.random() * 9000);
  SpreadsheetApp.getActiveSheet().appendRow([
    b.date, b.category, b.start, b.duration, b.serviceName, b.options, b.price, b.name, b.phone, b.comment, id, new Date(),
  ]);
  return ContentService.createTextOutput(JSON.stringify({ id })).setMimeType(ContentService.MimeType.JSON);
}
```

3. «Развернуть → Новое развертывание → Веб-приложение»: «Выполнять от имени: Я», доступ «Все». Скопировать ссылку.
4. В `data.js` заменить две функции:

```js
const API = "https://script.google.com/macros/s/ВАШ_ID/exec";

AVER.getBusySlots = async (dateISO, categoryId) => {
  const r = await fetch(API + "?date=" + dateISO + "&cat=" + categoryId);
  return r.json();
};

AVER.saveBooking = async (booking) => {
  // без заголовка Content-Type браузер шлёт text/plain, так Google не блокирует запрос
  const r = await fetch(API, { method: "POST", body: JSON.stringify(booking) });
  return r.json();
};
```

Честно об ограничениях: такой вариант подходит для портфолио и маленького салона. Он не защищает от двух одновременных записей на одно время и от спама. Для реального бизнеса лучше Supabase (бесплатный тариф, настоящая база) или готовый сервис записи с виджетом.

## Что ещё заменить перед реальным запуском

- Телефоны, e-mail, адрес, ссылки на соцсети (сейчас ведут на главные страницы Instagram/Telegram/Facebook).
- Отзывы, имена мастеров, историю салона, цены.
- Данные в блоке `application/ld+json` в `<head>` `index.html` (это для Google).
- Пометку «Демо-сайт» в футере.
